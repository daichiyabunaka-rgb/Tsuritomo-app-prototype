**バージョン**: v1.0（ドラフト）
**対象スコープ**: 第3弾「釣りとも」v1 / v1.5（ビジネスユーザー）
**作成日**: 2026年2月
**ステータス**: 要件確定待ち（法務レビュー項目あり）
**参考**: 第1弾「飯とも」・第2弾「犬とも」の要件定義書・実装（Meshitomo / Inutomo app-prototype）を本アプリのドメインに適用した第三弾。

## 1. 概要

### 1.1 目的

釣りをする人同士を、**顔ではなく趣味・中身ベース**でマッチングし、以下を実現する。

1. 一般ユーザー同士：今から・近くで、釣り仲間（居合わせ・相席・釣行の同行者）を探して一緒に釣る
2. 一般ユーザー：近くの釣り場（堤防・サーフ・桟橋・釣り可の水域）を探してGoogleマップで開く
3. ビジネスユーザー：AI接客・地図連携で、近隣の釣り人に店舗（釣具店・乗り合い船・釣り堀等）を知ってもらい来店・予約へつなげる
4. コミュニティ：常連・同じ釣り方の仲間同士のグループ、清掃イベント・釣行オフ会などのイベント企画

### 1.2 コンセプト上の設計原則

| 原則 | 内容 |
|---|---|
| 本人の顔画像禁止 | プロフィール画像は「釣りに関連する画像のみ」許可（釣果、タックル、釣り場の風景など）。**釣果・風景の写真はむしろ推奨**。本人の顔が写った画像はアップロード不可（モデレーションで拒否・削除） |
| 恋愛目的禁止 | 利用規約で「恋愛・異性交際目的の利用」を明示的に禁止。違反は BAN 対象 |
| 時限性 | 募集は期限付き（1〜3時間）。期限が来たら自動消滅。「今から」感が出会い系化を防ぐ |
| 距離の粗表示 | 正確な位置は非公開。「〜1km / 1〜3km」のような大ざっぱな距離のみ表示 |
| フィールドファースト | 釣り場・魚・環境の安全とルール遵守を最優先する文言・機能設計（無理な勧誘をしない、遊漁規則は必ず確認） |

### 1.3 前提と未確定事項（法務レビュー必須）

| 項目 | v1 の対応 | 備考 |
|---|---|---|
| 出会い系サイト規制法 | サービスの実質を「釣り仲間探し」とし、規約・モデレーションで異性交際目的利用を排除 | 弁護士による非該当性確認を必須とする。本人の顔画像禁止・時限募集制は非該当性の根拠になる設計 |
| 未成年利用 | **v1 は18歳以上のみとする**（第1・2弾と同じ） | 釣り場は酒を扱わないため「18歳以下も使用可」は v2 以降で法務確認の上検討 |
| 漁業調整規則・遊漁券 | 釣り場検索・釣果速報に「現地の案内・自治体の漁業調整規則・遊漁券の確認」を常時案内 | 釣り禁止区域への誘導が無い設計（fishing=no の場所は表示しない） |
| 水産資源保護 | サイズ制限・リリース規制（外来魚のリリース禁止等）も含めたルール遵守案内 | 違反行為を助長する文言・投稿はモデレーション対象 |
| 安全対策 | 堤防・船・水辺の事故防止を規約に明記。ライフジャケット・安全確認の案内。渡船・乗合船は船長の指示優先 | 釣行日の事故を想定した免責規約の整備 |
| 迷惑防止条例（客引き） | ビジネスユーザーの営業・AI接客はアプリ内完結とし、押しつけのない設計（一斉配信は行わない）。オプトアウト手段を常時提供 | 個別自治体・漁協への確認は開発中に実施 |
| 個人情報保護法 | 位置情報・嗜好データの第三者提供は「匿名加工統計」に限定 | 店舗ダッシュボードには集計値のみ表示 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 一般ユーザー | 無料で利用する釣り人（個人）。釣り仲間を探す側 |
| ビジネスユーザー | 有料プランで登録する店舗・事業者・個人営業主（釣具店、乗り合い船・渡船、釣り堀・管理釣り場、ボート・カヤックレンタル、フィッシングカフェ、ロッド・リール修理工房、アウトドア用品店など） |
| 募集（Recruitment） | 釣り人が近隣に向けて時限で発信する「参加者募集」（堤防・陸っぱり / 投げ・サーフ / 船・釣り堀）。投稿から1/2/3時間後に自動消滅 |
| 応募（Application） | 募集への参加申請。主催者が承認するとグループチャットが生成される |
| コミュニティ | 常設のグループ（魚種別オフ会、渡船常連会、釣り場の清掃クラブ等）。誰でも作成可、参加自由 |
| イベント | コミュニティまたは個人が企画する日程付きの集まり（釣行会、清掃活動、初心者講習会など） |
| 釣り場検索 | 現在地近くの釣りスポット（OSM: leisure=fishing、fishing=yes/permit の水域、man_made=pier）を一覧表示し、Googleマップ（標準URL）で開ける機能。ワンタップで「その釣り場で募集」も可能 |
| 釣果速報 | 海・川・湖の釣果を写真付きで近隣共有する機能。掲載終了は登録者が管理（FR-7） |

## 4. ペルソナ

### 一般ユーザー
- 20代〜50代、一人で釣行しがち、あるいは引っ越して釣り仲間がいない
- 「今から堤防に行きたいが、一人だと心細い・道具の持ちすぎ問題がある」「同じ釣り方の人と情報交換したい」
- 恋愛マッチングアプリには抵抗がある（恋愛目的でない人）
- 釣り仲間・相席仲間を作りたい

### ビジネスユーザー
- 釣具店・乗り合い船・渡船・釣り堀・管理釣り場・フィッシングカフェの経営者
- 「雨天・不漁続き・閑散時間に来店・乗船を増やしたい。新規の釣り人との接点が少ない」「AI接客で問い合わせ対応と、地図から来店への導線を強化したい」
- 月額数千円〜1万円程度の予算感で、新規顧客よりも「リピーター・常連コミュニティ」を増やしたい

## 5. 機能要件

### 5.1 会員登録・認証

| 要件 | 内容 |
|---|---|
| FR-1-1 | SNS 認証（Apple / Google / LINE）。v1 では電話番号認証を必須としないが、通報対策としてアカウント単位のレート制限を実装 |
| FR-1-2 | 登録時の必須入力：ニックネーム、年代（10歳刻み表示、生年非公開）、性別（非公開も選択可）、居住エリア（市区町村レベル）、興味カテゴリ（複数選択：サビキ・堤防釣り/投げ・サーフ釣り/ルアー・エギング/フライ・渓流釣り/管理釣り場・淡水/船釣り/夜釣り/釣った魚を食べる/釣り具・自作仕掛け/釣果・風景撮影/遠征・釣行旅行/釣り場の清掃・環境保護 の12種＋ユーザー自由追加）、釣りスタイル紹介の自由記述（140字、「釣りともステータス」） |
| FR-1-3 | **アイコンは写真アップロードまたは提供アイコンセットからの選択**。アップロード画像は **人の顔** を AI 顔検出で自動審査し、顔が検出された場合は拒否。**釣果・タックル・釣り場の風景は投稿可（推奨）** |
| FR-1-4 | 年齢確認：生年月日を入力させる（18歳以上チェック用）が、プロフィールには公開しない |
| FR-1-5 | 退会：アカウント削除時のデータ保持期間（アクティブデータ即時削除、バックアップ90日）を規約に明記 |

### 5.2 近くの釣り人・募集（コア機能）

| 要件 | 内容 |
|---|---|
| FR-2-1 | 「募集をかける」：以下を指定して募集を発信できる |
| | - ジャンル（堤防・陸っぱり / 投げ・サーフ / 船・釣り堀） |
| | - タイトル・本文（例：「今から堤防でサビキしませんか。アジの回遊あり。手ぶらOK」） |
| | - 条件設定：性別指定（任意）、人数上限、タックルの有無・貸し出しの言及（自由記述） |
| | - 有効期限（1 / 2 / 3 時間、期限切れで自動消滅） |
| | - 待ち合わせ場所：釣り場名（「近くの釣り場」タブからワンタップで設定可） |
| FR-2-2 | 「近くの人」リスト：現在地から粗い距離（〜1km / 1〜3km / 3〜5km / 5〜10km）で、近くのアクティブな募集・ユーザーを一覧表示。並び替え：距離×新着 |
| FR-2-3 | 検索：ジャンル、キーワード、距離、興味カテゴリでフィルタ可能。「探す」タブからは近くの店舗（業態・店名で検索可）と近くのコミュニティ・イベント（距離近い順）も辿れる |
| FR-2-4 | **近くの釣り場検索（本アプリの特別機能）**: 現在地周辺の実在の釣りスポットを OpenStreetMap（Overpass API）から取得し、近い順に一覧表示（距離バンド、営業時間、釣り可否）。対象は `leisure=fishing`（釣り場）、`fishing=yes/permit`（釣り可・要遊漁券の水域）、`man_made=pier`（桟橋・堤防）。**釣り禁止（fishing=no）・立入禁止（fishing=private）の場所は除外**する。`fishing=permit` は「要遊漁券」と表示する。各釣り場は「Googleマップで開く」（座標指定の標準URL）でGoogleマップに遷移する。「この釣り場で募集」ボタンで待ち合わせ場所を初期設定した募集を作成できる |
| FR-2-5 | 募集は同一ユーザーが同時に1件まで（スパム防止） |

### 5.3 応募・交流

| 要件 | 内容 |
|---|---|
| FR-3-1 | 応募：募集詳細から「参加したい」ボタンで応募。一声メッセージ（任意、140字） |
| FR-3-2 | 主催者は応募一覧から承認／却下。承認人数が上限に達したら募集は自動的に締切 |
| FR-3-3 | 承認されたメンバーでグループチャットが自動生成。参加者はその後も辞退可能 |
| FR-3-4 | 1:1 のダイレクトメッセージは募集への応募経由でのみ送れる設計（いきなり DM される対策） |
| FR-3-5 | 万一に備えた安全機能：ブロック／通報は一般ユーザー間と同一水準。釣行の安全（堤防・船の事故、ライフジャケット着用）を投稿時に案内 |

### 5.4 プロフィール・中身重視設計

| 要件 | 内容 |
|---|---|
| FR-4-1 | 趣味・嗜好の表現をリッチにする（よく行く釣り場、得意な釣り方、タックルの好み、釣った魚の食べ方）を「釣りともステータス」としてマイページに表示 |
| FR-4-2 | 過去の参加募集数、参加者からの評価（「また一緒に釣った」ボタン式、v1.5 実装）を表示 |
| FR-4-3 | ブロック／通報：非表示、通報（理由入力）。通報数が閾値超過で自動凍結 → 人力審査 |

### 5.5 ビジネスユーザー（v1.5）

| 要件 | 内容 |
|---|---|
| FR-5-1 | 店舗登録：店舗名、業態（審査対象：釣具店、乗り合い船・渡船、釣り堀・管理釣り場、ボート・カヤックレンタル、フィッシングカフェ・飲食、ロッド・リール修理工房、アウトドア・キャンプ用品店、その他）、住所、営業時間、写真（店舗・釣り場・スタッフの作業風景 OK。**本人の顔写真禁止は一般ユーザーと同じ基準**） |
| FR-5-2 | **AI接客（有料機能）**: ビジネスユーザーは店舗情報を登録するだけで、AI（LLM）が来店・乗船前の質問対応・案内（初心者対応、料金、タックルのレンタル、出港時刻等）を行う |
| FR-5-3 | **地図連携**: 近くの店舗をアプリ内マップ（OpenStreetMap タイル、APIキー不要）にピン表示。各店舗は「Googleマップで開く」（標準URL）。本開発で Google Maps SDK に移行し経路案内まで表示 |
| FR-5-4 | 効果測定: AI接客の応答数・来店導線・閑散時間のアクセス推移を店舗ダッシュボードに表示 |
| FR-5-5 | 課金：月額制（ライト／スタンダード／プレミアム）。決済は Stripe / RevenueCat 等の標準的な手段を利用 |

### 5.6 コミュニティ・イベント

| 要件 | 内容 |
|---|---|
| FR-6-1 | コミュニティ作成：誰でも可（名前、説明、カテゴリ、公開／承認制、地域）。魚種別オフ会、渡船常連会、釣り場の清掃クラブ等 |
| FR-6-2 | イベント：コミュニティに紐付けて日程・釣り場名・参加人数を設定し、参加受付 |
| FR-6-3 | ビジネスユーザーも一般ユーザーも同じコミュニティに参加可 |
| FR-6-4 | コミュニティ一覧（参加中・未参加とも）は**近い順にソート**する。コミュニティ自身の位置情報は持たず、メンバー・主催者の中で最も近い人までの距離で近さを定義する |

### 5.7 釣果速報の登録・検索

| 要件 | 内容 |
|---|---|
| FR-7-1 | 登録: 「海」「川・湖」の釣果を、対象魚・釣り方・サイズ、釣り場・ポイント、状況・タックル情報、**写真1枚（任意。ギャラリー/カメラ）**を入力して登録できる。位置は登録時の現在地（geohash）のみを持つ。写真は釣果・釣り場の風景の写るものとし、本人の顔画像が写った場合は投稿不可（アイコンと同じ基準） |
| FR-7-2 | 検索: 近くの登録を**距離近い順**に一覧。海／川・湖で絞り込み可。登録者へのDM導線を同画面に持つ（釣り方を聞きたい、一緒に行きたい） |
| FR-7-3 | 掲載終了: 登録者は「掲載終了にする」を設定でき、掲載終了の投稿は一覧から表示しない |
| FR-7-4 | 法務・安全設計: 遊漁券・釣り禁止区域は現地の看板や自治体の漁業調整規則を確認する案内を登録時・一覧に表示。**サイズ制限・リリース規制（外来魚等）の遵守も案内**。閉鎖水域・私有地の座標の晒し上げなど、個人や漁協が特定できる情報の記入を禁止案内 |

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| プラットフォーム | iOS / Android（Flutter）。Web 管理画面（モデレーション用） |
| 位置情報プライバシー | 位置情報は端末側で geohash（精度レベル5〜6程度）に変換して送信。サーバーには生の緯度経度を保持しない。退会時に即時削除 |
| セキュリティ | TLS 通信、認証トークン（短期＋リフレッシュ）、パスワードレス（SNS認証） |
| 応答性能 | 募集の一覧取得は P95 200ms 以内（キャッシュ活用）。プッシュ通知は P95 30秒以内。釣り場検索（Overpass）は30〜60秒かかり得るため端末内キャッシュ（30分・100mグリッド）を使う |
| 拡張性 | 趣味カテゴリ（第1弾:飯とも、第2弾:犬とも、第3弾:釣りとも、次弾:車/バイク/キャンプ等）はマスタデータ化し、アプリ再リリースなしで追加可能 |
| モデレーション | AI 審査（**人の**顔画像検出、禁止ワード）＋人力審査ワークフロー。通報 → 凍結 → 審査の SLA 48時間 |
| アナリティクス | 登録 → 募集投稿 → 応募 → 成立（チャット生成） → 実釣行（チェックイン）→ リピートのファネル KPI を計測 |

設計メモ：
- 募集の期限切れは毎分のバッチで `status` を `expired` に更新。クライアントは `_expires_at` を見て表示制御も行う（二重防護）
- 釣り場は外部データ（OpenStreetMap / Overpass API）を端末内にキャッシュし、「Googleマップで開く」URL は座標から組み立てる
- 距離検索は geohash プレフィックス照合で実装し、生の緯度経度での距離計算はクライアント側で行わない

## 9. KPI

|---|---|
| 起動初期（0〜3ヶ月） | 週次アクティブユーザー（WAU）、募集投稿数/日、募集あたり応募数、「釣り場」タブ→募集作成の転換率 |

| 収益化（6ヶ月〜） | ビジネスユーザー数（釣具店・乗合船・釣り堀）、AI接客経由来店数、解約率、LTV |

初期は釣り方の近さよりも「募集あたり応募数」が最重要。1.0を下回る場合、リリース地域を堤防・港密集地に絞る。

## 10. カテゴリ拡張戦略

第1弾「飯とも」、第2弾「犬とも」で共通のプラットフォーム（認証・募集・コミュニティ・地図連携・ビジネス課金）が確立できた前提で、第3弾「釣りとも」を選んだ根拠は：

1. 一般ユーザーの行動頻度が高い（釣りは週1以上の人が多い）
2. ビジネスユーザーが明確に存在し、課金対象（AI接客・地図連携）になる（釣具店、乗合船・渡船、釣り堀、ボートレンタル）
3. 周囲への「募集」が自然に多発する（ナインモンスターズ的方式の近隣勧誘が機能する）
4. 位置情報起点の特別機能（近くの釣り場検索）が屋外行動を促進する

次弾は「車/バイク」（ガソリンスタンド、カー用品店、ツーリング仲間）→「キャンプ」（アウトドアショップ、キャンプ場）を検討。
