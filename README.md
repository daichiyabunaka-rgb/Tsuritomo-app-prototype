# 釣りとも！（Tsuritomo）

**釣りでつながる。顔ではなく中身で。** 同じ趣味（釣り）の人同士を「今から・近くで」マッチングするスマホアプリのプロトタイプです。趣味特化型マッチングアプリの第3弾（第1弾: [飯とも！Meshitomo](https://github.com/daichiyabunaka-rgb/Meshitomo-app-prototype)、第2弾: [犬とも！Inutomo](https://github.com/daichiyabunaka-rgb/Inutomo-app-prototype)）。

ビジネスモデルは「一般ユーザー（釣り人）完全無料 × ビジネスユーザー（釣具店・乗り合い船・渡船・釣り堀・管理釣り場・フィッシングカフェなど）有料」。店舗向けの有料機能として **AI接客**（LLMによる来店・乗船前対応）と **地図連携** を提供する方針は第1・2弾と共通です。

## コンセプト（設計原則）

| 原則 | 内容 |
|---|---|
| 本人の顔画像禁止 | アイコンは**釣果・タックル・釣り場の風景のみ**許可。**釣果写真は推奨**、本人の顔が写った画像は不可（AI顔検出による自動審査は本開発で実装） |
| 恋愛目的禁止 | 釣り仲間探しに特化。規約とモデレーションで排除 |
| 時限募集 | 募集は1〜3時間で自動消滅。「今から」感を出会い系化防止に使う |
| 距離は粗表示 | 位置は「〜1km / 1〜3km」のバンド表示のみ。生の緯度経度は保持しない設計 |
| フィールドファースト | 釣り場・魚・環境の安全とルール遵守を最優先。遊漁券・漁業調整規則の確認を常に案内。無理な勧誘をしない |

**配布（ベータ）ビルドにモックデータは含めません。** モックの一般ユーザー・店舗・シード募集・シードコミュニティ・シードの釣果速報は開発・テスト用で、`kReleaseMode` で完全にオフになります。本開発では Supabase に実ユーザーが入るため、配布版は実際の登録者のみが表示されます（釣り場データは実データのため、ベータからも使えます）。

## 機能（プロトタイプ）

- メール会員登録 / ログイン / ログアウト（端末内モック認証、セッション永続化）
- GPS位置情報取得 → 近くの募集 / 釣り人 / 店舗（ビジネスユーザー）を一覧
- 募集（堤防・陸っぱり / 投げ・サーフ / 船・釣り堀、1〜3時間の時限）→ 応募 → 承認 → グループチャット自動生成
- 1:1のDM
- ブロック機能（相手には通知されません。ブロックすると相手のプロフィール・募集・DM部屋が非表示になり、マイページから解除できます）
- アイコン画像の投稿（釣果・タックル・風景。ギャラリー / カメラ、端末内永続化）
- **近くの釣り場を探す（本アプリの特別機能）**: 現在地周辺の**実在の**釣りスポット（OpenStreetMap / Overpass API: `leisure=fishing`、`fishing=yes/permit` の水域、`man_made=pier` の桟橋・堤防）を近い順に一覧表示。**釣り禁止（fishing=no）・立入禁止（private）の場所は含めません**。「要遊漁券」(`fishing=permit`) の表示もあり。「Googleマップで開く」でナビに遷移、「この釣り場で募集」ボタンで待ち合わせ場所を初期設定した募集を作成
- 近くの店マップ（OpenStreetMap）+ Googleマップで開く
- 「探す」タブから店舗（釣具店・乗合船等）を検索、近くのコミュニティ・イベントを距離順に閲覧・参加
- **釣果速報タブ（専用機能）**: 海・川・湖の釣果を近隣で共有（距離順・海/川湖の絞り込み・**写真添付**・登録者へのDM・掲載終了管理）。遊漁券・釣り禁止区域・リリース規制など、ルール遵守の案内を常時表示する設計
- コミュニティ・イベント（魚種別オフ会・渡船常連会・清掃クラブなど、誰でも作成・参加可。一覧は近い順にソート）
- 招待・紹介（SNS共有。一般ユーザーから友達へ、ビジネスユーザーから同業者へ）
- AI接客チャット（デモはルールベース。ベータではロック）

## 本開発への移行計画

1. **Supabase**: `docs/apply_all.sql` を適用し、`AuthService` / データ層を Supabase（Auth / Postgres+geohash / Realtime / Storage）に差し替え
2. **釣り場データ**: OpenStreetMap（Overpass API）で実データを取得（Google Places API との連携は本リリース時のオプションとして見送り。漁協・釣具店が持つ釣り場情報との連携も検討）
3. **AI接客**: ルールベースのモックを LLM API に置換（店舗情報 + 口調設定をプロンプトに渡す）
4. **モデレーション**: アイコン・釣果画像の AI 顔検出（**人の顔のみ**拒否。釣果の魚は許可するため Human/Animal/Fish の判別が必要）、禁止ワード審査
5. **地図**: 必要に応じて Google Maps SDK（APIキー）に移行し経路案内を表示
